## Root Causes

### Why the parser generates different output:

1. **Word Processing Engine**: When Word processes/saves XML, it:
   - Runs grammar/spelling checks → adds proof errors
   - Normalizes text node boundaries
   - May reflow text based on formatting
   - Resets some revision tracking IDs

2. **Text Node Normalization**: 
   - The parser likely uses Word's COM API or similar
   - Word splits text nodes based on formatting boundaries
   - This creates more granular `<w:r>` (run) elements

3. **Content Modification**:
   - Text changes (like "LINES" → "LINE") suggest Word may be:
     - Auto-correcting
     - Applying formatting rules
     - Or the parser is modifying content during extraction

4. **Metadata Changes**:
   - Revision IDs reset to '00000000' indicate new document state
   - Proof errors added reflect Word's grammar/spelling analysis

## Recommendations

To get more consistent output:

1. **Preserve Original Structure**: 
   - If using Word COM API, avoid opening/saving which triggers normalization
   - Use direct XML parsing instead of Word application

2. **Disable Auto-Features**:
   - Disable grammar/spelling checks before extraction
   - Disable auto-correct
   - Use "open as read-only" mode

3. **Text Handling**:
   - Reassemble text from `<w:t>` elements rather than relying on Word's splitting
   - Compare full text content, not individual elements

4. **Revision Tracking**:
   - If revision IDs matter, preserve them explicitly
   - Or normalize both files to remove revision tracking

5. **Comparison Strategy**:
   - Compare semantic content (full text) rather than XML structure
   - Ignore proof errors if they're parser-generated
   - Focus on actual content differences, not structural normalization

## Conclusion

The extracted file differs primarily because:
- **Word's processing engine** adds proof errors and normalizes structure
- **Text nodes are split more granularly** (more `<w:r>` elements)
- **Some text content is modified** (likely auto-correction or formatting)
- **Revision tracking is reset** (IDs changed to '00000000')

These are expected behaviors when using Word to process XML files, as Word applies its own formatting rules, grammar checks, and text normalization during document processing.
