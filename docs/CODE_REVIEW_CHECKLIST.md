# Code Review Checklist

Используйте этот чеклист при проверке Pull Request для предотвращения регрессий и обеспечения качества кода.

## Общие проверки

### Функциональность
- [ ] Код выполняет заявленную задачу
- [ ] Нет неиспользуемого кода (dead code)
- [ ] Нет закомментированного кода (если не требуется для документации)
- [ ] Изменения не ломают существующую функциональность

### Влияние на существующие функции
- [ ] Проверено влияние на связанные модули
- [ ] Обновлены зависимости (если добавлены новые)
- [ ] Обратная совместимость сохранена (если требуется)
- [ ] Миграции базы данных корректны (если есть)

## Качество кода

### Типы и безопасность
- [ ] Используются правильные TypeScript типы
- [ ] Нет использования `any` без необходимости
- [ ] Проверки на `null`/`undefined` присутствуют где нужно
- [ ] Валидация входных данных выполнена

### Обработка ошибок
- [ ] Ошибки обрабатываются корректно
- [ ] Пользователю показываются понятные сообщения об ошибках
- [ ] Критические ошибки логируются
- [ ] Нет "тихих" ошибок (silent failures)

### Производительность
- [ ] Нет очевидных проблем с производительностью
- [ ] Асинхронные операции используются правильно
- [ ] Нет утечек памяти (если применимо)
- [ ] Запросы к БД оптимизированы (если есть)

## Логирование и отладка

- [ ] Критические операции логируются
- [ ] Логи содержат достаточный контекст для отладки
- [ ] Используются helper функции из `logger.ts` (logOperationStart, logOperationEnd, etc.)
- [ ] Нет логирования чувствительных данных (пароли, токены)

## Тестирование

- [ ] Новые функции покрыты тестами (если применимо)
- [ ] Существующие тесты проходят
- [ ] Тесты проверяют граничные случаи
- [ ] Тесты проверяют обработку ошибок

## Безопасность

- [ ] Нет SQL инъекций (используется Prisma/параметризованные запросы)
- [ ] Нет XSS уязвимостей (если есть пользовательский ввод)
- [ ] Аутентификация/авторизация проверяется где нужно
- [ ] Чувствительные данные не логируются

## Документация

- [ ] Сложная логика задокументирована
- [ ] Обновлена документация API (если изменен API)
- [ ] Обновлен CHANGELOG.md (если есть пользовательские изменения)
- [ ] Комментарии объясняют "почему", а не "что"

## Feature Flags (если добавлена новая функция)

- [ ] Используется feature flag для новой функции
- [ ] Feature flag добавлен в `featureFlags.ts`
- [ ] Документирован в `.env.example` или документации
- [ ] Есть fallback на старую функциональность

## Frontend специфичные проверки

- [ ] Компоненты обрабатывают состояния загрузки
- [ ] Обрабатываются ошибки API
- [ ] Нет предупреждений в консоли браузера
- [ ] UI остается отзывчивым при длительных операциях
- [ ] Проверки на `null`/`undefined` для данных из API

## Backend специфичные проверки

- [ ] Валидация входных данных на уровне API
- [ ] Правильные HTTP статус коды
- [ ] Обработка таймаутов для долгих операций
- [ ] Транзакции БД используются где нужно
- [ ] Миграции протестированы

## Перед мерджем

- [ ] Код прошел все проверки выше
- [ ] PR имеет понятное описание
- [ ] Изменения протестированы вручную (если нет автоматических тестов)
- [ ] Нет конфликтов с основной веткой

---

## Быстрая проверка (для мелких изменений)

Если PR содержит только мелкие изменения (исправления опечаток, форматирование, документация):

- [ ] Изменения не влияют на функциональность
- [ ] Нет скрытых изменений в логике
- [ ] Форматирование соответствует стилю проекта
